## Summary

Adds an offline, on-device **voice search** capability to the shared **Search accounts and opportunities** bar across all three surfaces (Desktop, Web, VS Code extension). A mic button or **Ctrl+Alt+M** toggles capture; recognized speech is shown in a preview and inserted once at the caret/selection on stop, then reviewed/edited normally. No audio ever leaves the device and nothing is persisted.

This branch was implemented in an isolated worktree/session and was sitting unmerged and unpushed. This PR surfaces it after independent re-validation (see below).

## Design

- Desktop & local Windows VS Code: Electron/VS Code webviews deliberately block renderer-side mic access, so these use the local Windows-offline System.Speech engine via a fixed (non-interpolated) PowerShell helper invoked over -EncodedCommand, with dynamic data (vocabulary hints, wave file path) passed as JSON over stdin - no shell injection surface.
- Web: fully client-side Vosk WASM model in an isolated Worker, so the main page keeps its unsafe-eval-free CSP (only the worker's own response gets that allowance, scoped to default-src 'none'; script-src 'self' 'unsafe-eval'; connect-src 'self').
- Versioned contract (packages/common/contracts/voice.ts, voiceContractVersion = '1.0', strict Zod), shared orchestrator session host (packages/orchestrator/voice-input.ts), per-host adapters, shared UI logic/providers in apps/shared.
- Remote VS Code windows and server-side Web capture are explicitly disabled (verified by the transport-parity test).
- Full design/rationale: docs/research/Voice-Input-Research-and-Implementation-Plan.md; user-facing docs: docs/user-guide/VOICE-SEARCH.md.

## Independent validation performed in this PR

- npm run typecheck, npm run lint, npm test - all green (105 test files, 588 passed, 3 skipped).
- Security/privacy review: PowerShell adapter has no injection surface (fixed script + stdin JSON + shell:false); Electron IPC uses the existing assertTrustedSender pattern plus an extra main-frame check; Web CSP unsafe-eval is scoped only to the isolated worker response; no transcript/audio content is logged anywhere.
- npm run voice:model + npm run test:smoke:revamp (49 real cross-surface journeys, including the actual installed VS Code host and real recorded-audio transcription on Windows offline speech and browser Vosk): 49/49 passed after two small fixes made in this PR:
  - Rebuilt the Electron main/preload bundles (dist-electron/*), which were stale relative to the voice IPC source added by the original commit.
  - Hardened two web-voice.spec.ts post-stop assertions with an explicit 15s timeout (matching the tolerance already used elsewhere in the file) after hitting one flaky timeout under full-suite load; confirmed fixed via an isolated re-run (6/6) and a full re-run (49/49).
- Removed two stale .gitignore entries referencing voice research doc filenames that don't match the actual committed file.
